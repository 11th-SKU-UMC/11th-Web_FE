# 6주차 핵심 키워드

## Query key와 요청 상태

### Query key는 무엇인가요?

`queryKey`는 TanStack Query 캐시에서 각 조회 결과를 구분하는 식별자예요. 배열로 작성하며, 같은 key를 사용하는 조회끼리 같은 캐시 데이터를 공유해요. 따라서 어떤 데이터인지 구별하는 값과 요청 결과에 영향을 주는 값을 key에 포함해야 해요.

```tsx
// 목록 페이지마다 캐시를 따로 사용해요.
queryKey: ["movies", "list", { page }]

// 검색어와 페이지가 다르면 다른 검색 결과로 취급해요.
queryKey: ["movies", "search", { query, page }]

// 영화 ID마다 상세 데이터 캐시를 따로 사용해요.
queryKey: ["movies", "detail", movieId]
```

목록·검색·상세가 모두 `['movies']`처럼 같은 key를 쓰면 서로 다른 응답을 같은 캐시 항목으로 취급할 수 있어요. 검색어, 페이지 번호, 영화 ID처럼 요청 결과를 바꾸는 값을 key에서 빠뜨리면 다른 조건의 데이터가 잘못 재사용될 수 있어요. [공식 Query Keys 안내](https://tanstack.com/query/latest/docs/framework/react/guides/query-keys)

### `queryFn`은 무엇인가요?

`queryFn`은 서버에서 데이터를 가져와 Promise로 반환하는 함수예요. 요청이 성공하면 반환한 값이 `data`에 들어가고, 실패하면 오류 상태와 `error`를 확인할 수 있어요. 화면에서 필요한 상태를 표시하기 위해 `useQuery`가 이 결과를 제공해요.

```tsx
const movieQuery = useQuery({
  queryKey: ["movies", "detail", movieId],
  queryFn: ({ signal }) => getMovieDetail(movieId, signal),
});
```

### 조회 상태는 어떻게 읽나요?

- `isPending`: 아직 성공한 데이터가 없는 상태예요.
- `isError`: 마지막 조회가 오류로 끝난 상태예요.
- `isSuccess`: 사용할 데이터가 있는 상태예요.
- `isFetching`: 지금 네트워크 요청을 보내고 있는 상태예요. 처음 요청뿐 아니라 백그라운드 재조회도 포함해요.
- `isLoading`: 처음 데이터를 가져오는 중일 때 참이에요. `isPending && isFetching`과 같아요.

`enabled: false`로 자동 요청을 막았고 캐시 데이터도 없다면 `isPending`은 참일 수 있어요. 아직 데이터가 없기 때문이에요. 하지만 요청도 실행하지 않으므로 `isFetching`과 `isLoading`은 거짓이에요. 이때 `isPending`만으로 로딩 스피너를 띄우면 사용자는 실제 요청이 진행 중이라고 오해할 수 있어요. [공식 요청 상태 안내](https://tanstack.com/query/latest/docs/framework/react/guides/queries), [비활성화된 Query 안내](https://tanstack.com/query/latest/docs/framework/react/guides/disabling-queries)

## 캐시 수명과 재조회

### `staleTime`과 `gcTime`은 어떻게 다른가요?

| 옵션 | 무엇을 정하나요? | 시간의 기준 |
| --- | --- | --- |
| `staleTime` | 데이터를 얼마 동안 최신(`fresh`)으로 볼지 정해요. | 데이터가 마지막으로 성공적으로 갱신된 시점부터 계산해요. |
| `gcTime` | 사용하지 않는 캐시를 메모리에 얼마 동안 보관할지 정해요. | 해당 Query를 쓰는 화면이 없어져 `inactive`가 된 시점부터 계산해요. |

`staleTime`이 지나면 데이터는 `stale` 상태가 되어, 화면 진입·창 포커스 복귀·네트워크 재연결 같은 조건에서 다시 요청할 수 있어요. 시간이 지났다고 즉시 요청하거나 캐시가 삭제되는 것은 아니에요.

`gcTime`이 지나면 비활성 캐시가 메모리에서 제거돼요. Query를 사용하는 화면이 계속 열려 있으면 비활성 상태가 아니므로 `gcTime` 카운트다운은 시작되지 않아요. 기본 브라우저 설정은 `staleTime: 0`, `gcTime: 5분`이에요. [공식 기본값 안내](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults)

### stale이면 어떤 의미인가요?

- **fresh**: `staleTime` 안에 있어 최신으로 간주해요. 같은 key로 화면에 돌아와도 캐시를 바로 보여주고 재요청을 생략할 수 있어요.
- **stale**: 최신이라고 보장하지 않는 상태예요. 캐시 데이터는 남아 있고, 정해진 재조회 조건이 발생하면 서버에 다시 확인할 수 있어요.
- **inactive**: 그 Query를 구독하는 화면이 없는 상태예요. `gcTime`이 지나면 캐시가 삭제될 수 있어요.

따라서 `stale`과 `inactive`는 서로 다른 기준이에요. `stale`은 데이터의 최신성, `inactive`는 현재 사용하는 화면이 있는지를 말해요.

### 전역 설정과 조회별 설정은 어떻게 선택하나요?

대부분의 조회에 공통으로 적용할 기준은 `QueryClient`의 `defaultOptions.queries`에 설정해요. 이번 주차 프로젝트는 전역 `staleTime`을 1분으로 두고 있어요.

```tsx
const queryClient = new QueryClient({
  defaultOptions: {
    queries: { staleTime: 60 * 1000 },
  },
});
```

특정 조회만 데이터 변경 빈도나 최신성 요구가 다르면 `useQuery`에 개별 옵션을 지정해요. 이 프로젝트의 영화 상세 조회는 학습용으로 `staleTime: 30 * 1000`을 설정했어요. 개별 설정이 전역 기준보다 우선 적용돼요. `gcTime`도 같은 위치에서 전역 또는 조회별로 지정할 수 있어요.

## 이 프로젝트에서 직접 확인하기

1. 영화 목록에서 1페이지와 2페이지를 차례로 열고 Query Devtools에서 서로 다른 query key와 캐시 항목을 확인해요.
2. 다시 1페이지로 돌아가 1분 안에 재요청 없이 캐시 결과가 표시되는지 살펴봐요.
3. 영화 상세 화면을 열고 Devtools에서 30초가 지난 뒤 해당 Query가 `stale`로 바뀌는지 확인해요.
4. 상세 화면을 나가면 해당 Query가 `inactive`가 돼요. Devtools에서 캐시가 남아 있다가 `gcTime`이 지난 뒤 제거되는지 확인할 수 있어요.
